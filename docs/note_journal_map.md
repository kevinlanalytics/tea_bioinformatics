# Literature Note ↔ Zotero PDF Map

Maps each literature note in `Sources/Literature-Notes/` to its source PDF in
`~/Zotero/storage/`. Generated by querying `itemAttachments` in
`~/Zotero/zotero.sqlite` (parent item key → attachment key), not by title
matching, so it stays correct even when filenames diverge.

Columns:
- **citekey** — matches the note filename and the `citekey` frontmatter field
- **zotero item key** — the note's `zotero-link` target (`zotero://select/library/items/<key>`)
- **attachment key** — the folder name under `~/Zotero/storage/`
- **note path** / **pdf path** — relative to repo root / `~/Zotero/storage/`

Each PDF's markitdown conversion lives at `docs/markdown_pdf/<citekey>.md` (not tracked per-row
here — the path is always derivable from the citekey).

*Kept in sync by the `refresh-literature-notes` Claude Code skill*
(`.claude/skills/refresh-literature-notes/SKILL.md`), which detects new/changed Zotero
attachments and literature notes, updates this file, converts PDFs to Markdown via
`markitdown`, and rewrites each note strictly from that converted text. Invoke it by asking
Claude to refresh/sync/update the literature notes. Manual regeneration: query
`~/Zotero/zotero.sqlite`, table `itemAttachments` joined to `items` on `parentItemID`, matched
against each note's `zotero-link` key — see `scripts/scan_zotero_attachments.sh` in the skill
folder.
